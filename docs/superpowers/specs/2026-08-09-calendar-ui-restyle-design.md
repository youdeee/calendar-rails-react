# カレンダーUI Googleカレンダー風スタイリング 設計書

## 背景・目的

現状のフロントエンドはTailwind CSS(v4, `@tailwindcss/vite`)の導入自体は完了しているが、各コンポーネントにほぼクラスが付与されておらず素のHTML要素の見た目のまま動いている。本プロジェクトはGoogleカレンダーの模倣をポートフォリオの目的としているため、単なる装飾ではなく「本物に近い操作感・レイアウト」まで含めてスタイリングする。

調査の過程で、スタイリング前提となる機能的な欠落が2点見つかったため、本設計のスコープに含める。

1. `CalendarPage` の `currentDate` が `useState` の初期値(今日)に固定されており、月・週・日を移動する手段が一切ない
2. `all_day` はバックエンド(カラム・API・シリアライズ)は対応済みだが、フロントエンドのフォームに終日予定を作成するUIがない

## スコープ

**含む**:
- ヘッダーの再設計(ロゴ・今日ボタン・前後ナビ・年月表示・表示切替・ユーザーアバター/ログアウト)
- 月表示のGoogleカレンダー風グリッド化(枠線・今日ハイライト・イベントチップ・件数キャップ)
- 週表示・日表示を「予定の一覧」から「0〜24時の時間軸グリッド」へ作り直し
- 予定作成・編集モーダルのオーバーレイダイアログ化
- 終日予定の作成・編集UI(トグル + 日付入力)
- 上記に伴う日付ナビゲーション機能の追加

**含まない(将来拡張)**:
- 週表示・日表示での時間軸上のドラッグ&ドロップ(時刻変更)。月表示の日付間ドラッグは現状維持
- 複数日にまたがる終日予定(開始日=終了日の単日のみ対応)
- サイドバー(ミニ月間カレンダー・複数カレンダーの色分け)
- 予定の色分け(バックエンドに色フィールドがないため全イベント単色)
- 月表示での「+N件」クリック時のポップオーバー展開(テキスト表示のみ)

## デザインシステム

- アクセントカラー: Googleブルー系。`index.css` に `@theme` ブロックで `--color-brand: #1a73e8` 等を1〜2色追加し、それ以外はTailwind v4標準パレット(`gray-*`, `blue-*`)を使う。新規に色設定ファイルは作らない
- フォントはブラウザのデフォルトsans-serifスタックのままとし、Webフォント読み込みは追加しない(CSPの `style-src` 制約もあり、追加の外部リソース読み込みは避ける)

## コンポーネント別設計

### CalendarPage(ヘッダー・状態管理)

- `currentDate` を `useState` + セッターに変更し、ナビゲーション操作で更新できるようにする
- ヘッダーに以下を配置: ロゴ文字列、「今日」ボタン、`← →` ボタン、表示中の年月/週/日ラベル、月/週/日の表示切替(セグメントコントロール風のボタン群)、右端にユーザーアバター画像(`user.avatar_url`) + ログアウトボタン
- 「予定を追加」ボタン押下時、`EventFormModal` に現在表示中の日付(`currentDate`)をデフォルト日付として渡す
- ナビゲーション用の日付計算(`addMonths`, `addWeeks`, `addDays`)は `dateUtils.ts` に純粋関数として追加し、単体テストを書く

### MonthView

- グリッドセルに枠線を付け、日付番号をセル右上に配置
- 今日のセルは `bg-blue-50` を維持(既存テストとの互換性のため)
- イベントは色付きの角丸ピル(チップ)として表示
- 1セルあたりの表示件数を3件にキャップし、超過分は非インタラクティブな「+N件」テキストを表示する純粋関数(`groupEventsByDay.ts` 付近、または新規ヘルパー)で算出

### WeekView / DayView(時間軸グリッドへの作り直し)

- 0時〜24時の1時間刻みの行を持つグリッドを新規実装
- 終日予定(`all_day: true`)は時間軸の上に専用の行で表示
- 時間指定の予定は、開始・終了時刻から縦位置(top%)と高さ(height%)を算出して絶対配置する。算出ロジックは新規ファイル `timeGridLayout.ts` に純粋関数として切り出し、単体テストを書く
- 現在時刻に赤い横線を表示する。日表示では表示中の日が今日の場合のみ全幅に表示し、週表示では表示中の週に今日が含まれる場合のみ「今日の列」だけに表示する
- 時間軸上のドラッグ&ドロップは実装しない(将来拡張)

### EventButton / EventChip

- 色付きの角丸ピル型に統一。月表示はチップ、週/日表示は時間軸上のブロックとして流用できるよう、共通の見た目(背景色・角丸・テキスト省略)は共有しつつ、位置指定(absolute)は呼び出し側で行う

### EventFormModal

- 画面中央のオーバーレイダイアログに変更(背景を半透明の黒でオーバーレイ、カードは白背景・角丸・シャドウ)
- 「終日」チェックボックスを追加
  - **新規作成時のデフォルトはON**。日付は `CalendarPage` から渡された `currentDate` を初期値にする
  - **編集時**は対象イベントの実際の `all_day` 値を反映する(新規作成時のみデフォルトON、編集は現状維持)
  - 終日ONの間は、開始/終了の2つの `datetime-local` 入力の代わりに1つの `date` 入力を表示する。送信時は選択日の00:00(ローカル)を `start_at`、翌日00:00を `end_at` とし `all_day: true` を付与する
- 終日をOFFにしたとき(時間指定モードに切り替えたとき)
  - 開始日時は、終日用に選択されていた日付の9:00を初期値とする
  - 終了日時は「開始日時 + 1時間」を自動セットする
- 「よしなに」自動追従: 開始日時を変更したとき、終了日時が未入力、または開始日時以下(不正な状態)であれば、自動的に「開始日時 + 1時間」を再セットする。終了日時をユーザーが手動で有効な値に変更した後は、それ以降の開始日時の変更で上書きしない(終了日時に対する「ユーザーが最後に手で触ったか」を1つのフラグで管理する)

## テスト方針

- 既存のRTLテストはrole/label基準のクエリが中心のため、大部分は無改修で通る想定。`MonthView.test.tsx` の今日ハイライト判定(`bg-blue-50`)はクラスを維持するため無改修
- 新規テスト:
  - `dateUtils.ts`: 月/週/日の加算関数
  - `timeGridLayout.ts`: 時刻からtop%/height%を算出するロジック(日をまたぐ・0時ちょうど・終日などの境界値を含む)
  - `CalendarPage`または`EventFormModal`: 終日トグルのデフォルト値、終了日時の自動追従ロジック
  - 日付ナビゲーション(今日ボタン・前後ボタンで表示範囲が変わること)
